# Перенос сервиса рыночных данных

Краткая рабочая процедура переноса БД рыночных данных между серверами обычным PostgreSQL без расширений. Полные требования: [PRD, раздел данных](../prd/data.md).

## Полный перенос сервиса (backup/restore)

1. Остановить писателя: переменная окружения `BYBIT_INGEST_ENABLED` не задана или сервис остановлен. Старый и новый писатели не работают одновременно.
2. Сделать логическую копию БД сервиса:
   `pg_dump -U <user> --no-owner --no-privileges <market-db> > market-data.sql`
   Dev-окружение: `infra/dev/backup-market-data.sh [файл]`.
3. Восстановить в чистую базу целевого сервера (без расширений):
   `createdb <market-db> && psql -d <market-db> -v ON_ERROR_STOP=1 < market-data.sql`
   Dev-окружение: `infra/dev/restore-market-data.sh <файл> [база]`.
4. Сверить: количество инструментов/свечей, границы и пропуски покрытия (`GET /v1/instruments/:id/coverage`), перенесённые задания и cooldown (`backfill_jobs`, `service_state`).
5. Запустить сервис на новом узле, убедиться в readiness, переключить адрес API у клиентов. Исходная копия не удаляется автоматически.

Секреты (ключи API, `API_KEYS`) переносятся отдельно защищённым способом и не входят в дамп.

## Независимый экспорт рядов

`npm run export -w services/market-data -- <каталог>` пишет `candles.csv` (колонки из `manifest.json`) и `manifest.json` с единицами, семантикой времени (Unix-секунды, время открытия минуты), идентичностью инструментов и покрытием. Экспорт читается без работающего сервиса, БД приложения и служебных таблиц; decimal-значения передаются строками без потерь.

## Автоматические проверки

Интеграционные тесты `transfer.test.ts` проверяют идентичность восстановленной копии (свечи, покрытие, задания, cooldown) и отсутствие повторных запросов к бирже для уже сохранённой истории. Локально тест требует запущенный dev-контейнер; в CI пропуск (нет docker exec к service-контейнеру).
